# Terrarium Tickets on Cloudflare

Self-contained, deployable full-stack application source generated by the
Terrarium control plane: a React SPA (vite, in `web/`) served as Cloudflare
Assets by the same Effect-native Worker that hosts the Tickets domain on
Durable Objects, with D1 alongside. The SPA uses TanStack Router (file routes,
an auth-guard root route) + TanStack Query (server state) + an
Effect-`HttpApiClient`-generated typed client (no hand-rolled fetch).

## Commands

```sh
pnpm install
pnpm --dir web install

# local dev: workerd (real Durable Objects + local D1) on :1337,
# vite dev server with hot reload + API proxy on :5173
pnpm dev          # alchemy dev  (the worker)
pnpm dev:web      # vite dev    (the frontend, in another shell)

# build + deploy + tear down
pnpm deploy       # builds web/dist, then alchemy deploy
pnpm destroy
```

`deploy` requires Cloudflare credentials understood by Alchemy
(`CLOUDFLARE_ACCOUNT_ID` plus either `CLOUDFLARE_API_TOKEN`, or an
authenticated Alchemy profile). Configuration: `WORKER_NAME`,
`D1_DATABASE_NAME`, and `STACK_NAME` (all have per-app values supplied by the
scaffold).

The Worker hosts the Tickets model on Cloudflare Durable Objects. Its D1
migration provisions `app_metadata`; `GET /d1-health` proves the binding. The
canonical ticket list remains a Domain view in a Durable Object.

## Optional auth seam

Auth is off by default. Set `TERRARIUM_ISSUER` (and optionally
`TERRARIUM_AUDIENCE`, default `<app>.terrarium.local`) at deploy/dev time and
every API surface requires a bearer token from that issuer — verified against
its OIDC discovery document + JWKS. `/health` and `/auth/status` stay public;
the SPA reads `/auth/status` to decide whether the session applies (the root
route's guard bounces to the hosted sign-in on a 401 — there is no logged-out
UI state).

Local proof (the deployed Worker cannot reach a localhost issuer):

```sh
pnpm --filter @terrarium/dev-issuer start   # in another shell
TERRARIUM_ISSUER=http://127.0.0.1:4010 TERRARIUM_AUDIENCE=my-app pnpm dev
# then the root route's guard bounces to /auth/login, or:
curl -H "Authorization: Bearer $TOKEN" http://localhost:1337/whoami
```

When the hosted OIDC provider (Logto) is live, only the two env values
change; the SPA's bounce goes to the hosted sign-in page instead.

## Smoke

```sh
curl "$WORKER_URL/health"
curl "$WORKER_URL/"                      # the SPA
curl "$WORKER_URL/d1-health"
curl -X POST "$WORKER_URL/OpenTicket" -H 'content-type: application/json' \
  -d '{"target":"demo-1","input":{"title":"Real deployment","reporter":"demo"}}'
curl "$WORKER_URL/TicketById/demo-1?stream=Ticket%2Fdemo-1&version=1"
```
